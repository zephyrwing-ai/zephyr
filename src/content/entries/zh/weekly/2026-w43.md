## Raycast 的技术重构

[Raycast 的技术深度文章](https://www.raycast.com/blog/a-technical-deep-dive-into-the-new-raycast)写的是 Raycast 在重构软件时如何做出决策，以及他们进行技术选型时如何按照约束分层考量。共四层：Raycast 外壳、前端、后端、Rust 性能下放。

外壳选型涉及两套 UI 栈以及人才的考量。前端涉及软件本身强 OS 集成。后端考虑到原本代码有 JavaScript 生态，因此需要兼容。Rust 负责性能问题，但是要怎么定义约束？约束既有外部约束，也有内部约束。Raycast 既考虑了招聘市场，也考虑了自身资源，比如维护、系统状态等等。

1. 从产品出发，什么是这个产品吸引用户不可缺少的部分，那么什么样的技术能够保持甚至优化这个部分的建设。
2. 软件中哪些功能频繁变化，考虑到维护性对用户体验的影响，还有性能对用户体验的影响。
3. 对边界的定义：能力归属、数据流、权限与安全。例如全局热键、剪贴板、辅助功能、文件系统权限、窗口管理，只有 OS 或原生层能够提供，因此边界在原生壳。

## Wise 的设计决策

[Wise 设计决策背后的逻辑](https://x.com/bearliu/status/2113273422738244085)从“为什么”开始。做出好的设计需要好的决策，看懂好的设计需要问出好的问题。背后本质都是在问为什么：对一个设计进行溯源，得出结果，为什么这样设计，体现什么目的，为什么不那样进行设计，不同点的设计决策是什么。

Wise 的注册界面是一个计算器。Wise 的优势是便宜，他们是如何体现便宜的？他们没有使用图片对比，直接告诉用户自己比较便宜，而是放了一个计算器。为什么放一个计算器让用户能够直接计算？

## 多客户端开发的技术选择

[关于多客户端开发的三篇文章](https://x.com/HiTw93/status/2112526198807183766)介绍了作者在多客户端下的技术选择思考和开发经验。从这三部曲中可以看出作者的工程能力，以及开发涉猎的广泛。文章简单介绍了 Web 开发、跨端开发、原生开发之间的区别，以及一些技术的迭代。

如何进行技术选型？你需要知道技术的优缺点，同时结合软件的业务场景开展相应的工作。如果你的软件依赖底层操作系统，那么就使用原生开发，可以提升性能，并且享有底层系统优化带来的好处。文章随后讲到设计系统：如果后面有一套自己的设计系统，那么在后续开发时会省去很多事情，除非这个场景需要一套新的设计系统。最后提到了 IPC，也就是进程间通信。一个软件不一定使用一种语言编写：例如一个问题用 Swift 写很麻烦，但是 JavaScript 有很好的实现，那么可以考虑用 Swift 调用 JavaScript 来实现。
